## 0.1.1 消息来源兼容修复

用户真实 DSH 轮次报告 `format v4 message requires a producer-owned source kind`。0.1.0 的提醒使用旧式 `source: { kind: 'plugin', plugin: 'dsh-agent-docs' }`，未遵循当前消息来源协议。0.1.1 改为插件自有来源 `source: { kind: 'agent-docs', form: 'instructions' }`。

宿主回归测试现在将提醒实际追加到真实 Session，而不只是收集到数组；旧源码下该测试失败。此修复不代表已完成真实在线模型维护任务验收；桌面/浏览器中应升级后再次完成正常轮次验证。

## 工具与命令

### 将源码规则同步到本机

在项目根目录执行 `npm run sync:rules`，将 `rules/` 四份文件同步到当前用户的 `.agent-docs/dsh` 和 `.agent-docs/codex`（本机为 `C:/Users/DELL/.agent-docs`）。这是显式覆盖操作；仅覆盖内容不同的同名规则，旧文件先备份到 `.agent-docs/.backups/rules-<时间>-<随机标识>/`，并核对 SHA-256。一致的文件跳过，不产生重复备份，也不删除其他文件。

预览：`npm run sync:rules -- -WhatIf`。只同步一端：`npm run sync:rules -- -Platform dsh`。自定义根目录：`npm run sync:rules -- -TargetRoot D:/AgentDocs`；目标仍为其下 dsh、codex 子目录。若插件显式配置了其他 rulesDir 或 AGENT_DOCS_RULES_DIR，请核对实际使用路径，此脚本不自动修改或发现这些配置。

脚本独立于构建与打包；创建脚本不会自动同步，执行同步也不会修改插件安装包或缓存。已有运行环境下次读取用户规则时生效。

本机使用 Node `C:/Program Files/Volta/node.exe`（24.19.0）、npm `C:/Program Files/Volta/npm.exe`、DSH `D:/ProgrameFiles/Volta/bin/dsh.cmd`（0.2.2-rc.1）。ZIP 打包使用 `C:/Users/DELL/.cache/codex-runtimes/codex-primary-runtime/dependencies/native/powershell/pwsh.exe`，归档检查使用 `C:/Windows/system32/tar.exe`。没有新增构建依赖。重新打包需 PowerShell 7 的 pwsh 在 PATH 中；Windows PowerShell 5.1 的本机 ZipFile 类型不可用，因此未用于打包。

源码默认规则位于 `rules/`；修改后执行：

```powershell
npm run build
npm test
npm run pack
npm run verify:packages
```

构建复制共享规则与辅助模块到两个插件，打包后不依赖 monorepo 路径。DSH 测试需匹配宿主依赖；本机根 node_modules 是指向 `C:/Users/DELL/.dsh/profiles/node_modules` 的目录 Junction，仅用于开发，不进入发行包。其他机器应在开发目录安装与插件 peer 声明匹配的依赖。
