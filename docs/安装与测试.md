# 安装与测试

## 当前交付与路径

当前版本 0.1.7：完整安装包、DSH TGZ、Codex ZIP 和 SHA256SUMS.txt，包含 Project 当前系统映射规则调整，独立三场景语义验收尚未完成。GitHub 下载命令见[源码 README](https://github.com/Songyanglin-curious/agent-docs#github-包)，附件见 [v0.1.7 Release](https://github.com/Songyanglin-curious/agent-docs/releases/tag/v0.1.7)。本地完整包名为 `agent-docs-0.1.7-安装包.zip`，GitHub 对应附件使用 `agent-docs-0.1.7-bundle.zip`，内容相同。本手册提供本地安装、查询与完整卸载步骤。

| 内容 | 默认位置 |
| --- | --- |
| DSH 插件 | DSH 自己管理的 Profile/node_modules/dsh-agent-docs |
| Codex 登记用源 | ~/.codex/plugins/local/codex-agent-docs |
| Codex 安装缓存 | Codex 原生插件管理器维护 |
| Codex 个人市场 | 宿主标准 ~/.agents/plugins/marketplace.json，仅增删本插件条目 |
| 默认规则 | 各自安装包 defaults/，不复制到用户目录 |

不再创建 ~/.agent-docs，也不默认产生备份。只有显式配置自定义目录时，才补齐缺失规则且保护用户内容。遗留的旧目录不会被插件自动导入、迁移或删除。

## DSH 安装与卸载

Node.js 22+，目标 DSH 服务须满足 TGZ 中声明的 peer 范围。在项目根目录执行或替换为解压后实际路径：

```powershell
dsh plugin --profile web add 'D:/mycode/agent-docs/dsh-agent-docs-0.1.7.tgz'
dsh plugin --profile web remove dsh-agent-docs
```

不要连续执行两条，第二条仅在卸载时使用。--offline 只有整个 Profile 的依赖缓存齐全时适用。安装后重启对应实例，确认 agent_docs_rules 工具可用，info 的 rulesDir、init、maintain 均指向包内 defaults。

卸载后检查依赖及 bundle 条目消失，真实 Cordis 宿主卸载后工具与监听失效；包管理器共享缓存可以保留，不视为插件额外写入。

## Codex 安装与卸载

解压 codex-agent-docs-0.1.7.zip，PowerShell 执行（替换解压目录）：

```powershell
& '<解压目录>/install-codex.ps1'
codex plugin add codex-agent-docs@personal-local --json
codex plugin list --marketplace personal-local --json
node "$env:USERPROFILE/.codex/plugins/local/codex-agent-docs/scripts/rules-cli.mjs" info
```

确认 version=0.1.7、installed=true、enabled=true。规则路径必须是包内 defaults。桌面应用重启后新建聊天；Hook 升级可能需要重新审阅，安装脚本不会伪造信任记录。

完整卸载：

```powershell
codex plugin remove codex-agent-docs@personal-local --json
& '<解压目录>/uninstall-codex.ps1'
```

原生命令移除安装缓存与启用状态；清理脚本移除登记用源及本插件市场条目，保留共享市场和其他插件。脚本不会额外制造备份。显式自定义目录不会被卸载删除。

install/uninstall 脚本支持 -UserRoot 指定独立测试根目录，仅用于隔离脚本的生命周期测试；日常使用不传此参数。不要把测试登记误当成桌面客户端安装。

## 规则定位与自定义

默认不需要同步。显式设置 DSH rulesDir 或环境变量 AGENT_DOCS_RULES_DIR 才启用自定义目录，必须是绝对路径。DSH rulesDir 优先。环境变量改变后需重启宿主，规则正文改变下次读取生效。旧版 ~/.agent-docs 不会默认读取。

## 验证边界

自动检查覆盖归档清单、包内四规则与源码一致、解压后的 Hook 子进程、规则默认更新与显式自定义保护、真实 Cordis 工具和监听卸载。安装后还需单独核对版本、实际返回路径和宿主外目录是否产生。

以下语义行为需真实模型观察，自动测试或安装回读不能代替：

1. 普通无 Docs 轮次不自动初始化。
2. 显式初始化创建四核心目录及索引，其他文件按需创建，验证材料约定在根目录 evidence/ 或项目已有位置。
3. 同一 Agent 正常轮次只提醒一次；续接后放行，用户禁改时不修改。
4. 对照有效 Design 或用户要求核验，Project 反映实现和验证边界，不强制生成 Spec/任务清单。
5. 逐层索引可达且只概括直接子级，外部集合、主题引用与临时证据入口各有适当位置。
6. 稳定项目偏好可提炼，冲突和扩大范围需确认，不自动跨项目推广。

出现失败应记录实际版本、规则路径、输入与观察结果，不将配置展开、路径检查标为模型闭环通过。

## Project 当前系统映射的语义验收

以下是规则研发或专项验收方案，不是每轮 Hook 的强制流程，也不是已经通过的测试结果。日常初始化和维护仍由原 Agent 完成，不要求额外 Agent 或长期检查报告。产物标准统一见规则源 spec.md 的 §4.6；先确认宿主实际读取的是待验规则，再开展场景测试。

### 验收依据与上下文隔离

1. 独立事实调查者根据代码、配置、测试和可取得的运行结果，建立主要能力及关键事实的验收依据，记录证据位置和未确认边界；不能只依据待测 Project 生成答案。实现事实与现场验证结果分别记录，不因代码存在就宣称现场通过。
2. 建模或维护 Agent 获得正常任务输入和项目实现，执行待验规则；不预先提供答案或指定应修改哪些 Project 文件。不允许验收者反向补写产物来制造通过。
3. 阅读测试使用另一个隔离上下文，仅提供生成的 Project、问题及“无法从文档判断时明确说明”的要求；不提供源码、建模底稿、事实答案、原会话或其他 Docs。经链接也不得访问这些材料，避免知识泄漏。
4. 将回答及其 Project 引用位置与独立事实对照，检查遗漏、错误和冲突；同时将主要能力清单与文档对照，不能以几个问题答对代替能力覆盖。阅读者的常识猜测不算文档表达通过；若无法隔离上下文，只能记录自查结果，不能称为独立验收。

### 三个场景

在隔离项目副本中执行，保留输入、规则路径、事实依据、文档差异、阅读回答与判定；不直接改写日常项目或真实数据。使用 Agent Docs 的显式初始化入口或真实日常 Hook，分别记录规则执行效果与 Hook 投递效果，手动提醒不能代替自动触发验收。

| 场景 | 前置条件与输入 | 通过条件 |
| --- | --- | --- |
| 正向维护 | AI 接入实现已存在，Project 保留缺失或失实描述；本轮仅确认联调事实，没有代码修改，也不点名 Project。 | 自动检查 Project，沿能力及关系分析影响，完成必要的局部与整体修正；不写开发历史、不扩大无关范围。没有 Hook 投递证据时，仅能判定规则执行部分。 |
| 负向维护 | 同样的实现与确认事实，但 Project 已准确、充分表达相关行为与关系。 | 检查后无需修改，不制造能力条目、流水账或空报告。 |
| 初始化 | 一个建模者未接触的已有实现项目；独立事实调查已确定边界、主要能力及行为。 | 全貌、深入调查、综合建模和覆盖核对有可核对依据；Project 满足 spec §4.6，未完成范围明确。只有概览、模块或路径清单不能通过。 |

AI 场景至少检查以下事实，答案以所测版本的独立调查为准，不将此清单当作永久正确的实现契约：

- 页面所选、讨论对象、本轮固定目标和工具显式目标的关系及优先顺序。
- 目标固定与草稿可写条件的区别，离开规则页面或切换其他方案后的实际结果。
- 候选配置、编辑器草稿与已保存方案配置的区别，以及最终保存由谁完成。
- 页面回执、用户取消、失败或超时各自意味着什么，不能将接受请求当作应用成功。
- AI 平台、本地后端、工具执行器和规则编辑器的职责与交接，整体介绍与局部说明是否一致。

分开记录两层结论：**规则交付**检查源规则、双端构建与归档、安装后实际读取路径和内容；**模型能力**检查真实 Agent 的建模、维护与隔离阅读结果。任一层未执行或只部分通过时明确标出，不能互相替代。
