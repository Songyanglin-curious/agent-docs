# 安装与测试

## 交付物

跨机器复制 `agent-docs-0.1.3-安装包.zip` 即可，解压后包含两个插件包、本手册、校验和与四份规则原文。新机器首次调用会从包内默认值创建用户规则；若目标机器已有旧用户规则，升级不会覆盖，请备份后手工比较并按需替换四份文件，或设置一个新的规则目录。

在另一台机器安装 DSH 时，把示例包路径改成解压后的实际绝对路径，Profile 名改成该机器实际使用的名称（例如 web）。`--offline` 要求整个 Profile 的依赖缓存齐全；若提示其他已有插件版本找不到，可去掉该参数允许联网解析，Agent Docs 本身仍从本地 tarball 安装。不要因此降级无关插件。

- `dsh-agent-docs-0.1.3.tgz`：DSH 本地离线插件包。
- `codex-agent-docs-0.1.3.zip`：Codex 桌面版插件、市场文件、登记脚本和本手册。
- `SHA256SUMS.txt`：包校验和。

Node.js 22+ 必须在宿主 PATH 中。DSH 包不携带整个 DSH；离线安装需目标 Profile 已具备匹配的 DSH 服务及 Schemastery。Codex Hook 无 npm 运行依赖，也不需要安装 Codex CLI。

## DSH Web 从 GitHub 安装（推荐）

在 PowerShell 执行，后续升级时同步替换标签和文件名中的版本号：

```powershell
dsh plugin --profile web add 'https://github.com/Songyanglin-curious/agent-docs/releases/download/v0.1.3/dsh-agent-docs-0.1.3.tgz'
```

远程安装需要联网，不加 `--offline`。安装后重启对应 DSH Web 实例；检查 Profile 的依赖已指向上述 URL、bundle 包含 `dsh-agent-docs`，并确认工具 `agent_docs_rules` 可用。安装结果与自动维护的完整模型闭环分别验收。

GitHub 源码仓库不提交 dist、node_modules、本机环境文件和测试证据；发行包及 SHA256SUMS.txt 通过 Release 提供。不要用源码 ZIP 代替插件 TGZ。

## DSH 本地安装

在目标 Profile 所属 DSH 版本为 0.2.2-rc.1 时，替换以下绝对包路径并运行：

```powershell
dsh plugin --profile code add 'D:/mycode/agent-docs/dist/dsh-agent-docs-0.1.3.tgz' --offline
dsh --profile code --dump-config
```

读取结果应有 `id: agent-docs`、`name: dsh-agent-docs`、enabled 为 true。配置展开不等于运行验证，随后重启相应 DSH 实例，确认插件没有加载错误，Agent 工具包含 `agent_docs_rules`。

在对话中说“用 Agent Docs 初始化当前项目 Docs”，Agent 应调用 `agent_docs_rules({mode:'init'})`，读取返回路径并增量初始化。查看配置可调用 info 模式。调用该工具返回路径本身不表示 Docs 已生成。

DSH 可在 Profile 补丁中覆盖：

```yaml
- id: agent-docs
  config:
    enabled: true
    rulesDir: D:/AgentDocsRules
```

补丁替换整个 config，因此要保留 enabled。卸载使用 `dsh plugin --profile code remove dsh-agent-docs`，然后重启实例；用户规则保留。

## Codex 桌面安装

GitHub 下载、校验及安装的完整 PowerShell 命令见 [README](../README.md#从-github-安装-codex-桌面插件)。当前支持 `codex plugin` 的客户端在登记后运行 `codex plugin add codex-agent-docs@personal-local --json` 完成安装，再用 `codex plugin list --marketplace personal-local --json` 回读版本与启用状态；仅运行登记脚本不等于安装完成。桌面应用重启、新聊天与 Hook 审阅仍需独立确认。

1. 解压 ZIP 到稳定目录，例如 `D:/Tools/agent-docs`。保持点号目录 `.agents`、`.codex-plugin`。
2. 在 PowerShell 运行解压目录的 `install-codex.ps1`。脚本将插件复制到用户主目录 `.agent-docs/plugins/codex-agent-docs`，增量登记个人市场 `~/.agents/plugins/marketplace.json`，备份已有目录及市场文件；不修改其他插件或伪造信任。
3. 重启 Codex 桌面应用。在插件目录选择个人本地市场，找到 `codex-agent-docs` 并安装/启用。如果独立 Codex 桌面版本不显示此市场，不修改内部缓存冒充安装，保留包并按下面的手工 Hook 兼容方式测试。
4. 在输入区点击 Review hooks 或进入 Settings > Hooks，审阅 Agent Docs Stop Hook，确认命令指向插件脚本，再信任。未审阅时宿主可能跳过 Hook，不能据此认定插件失败。脚本或 Hook 升级后可能需重新审阅。
5. 新建项目聊天，调用插件的 init 技能，或明确说“用 Agent Docs 初始化当前项目 Docs”。规则查看使用 rules 技能。

官方参考：[插件打包与本地市场](https://developers.openai.com/plugins/build/plugins)、[Hook 协议与桌面审阅](https://learn.chatgpt.com/docs/hooks)。文档描述的是受支持本地客户端，独立桌面版的实际暴露能力需要现场验证。

### 桌面版不加载本地市场时的兼容测试

这只是用户 Hook 方式，不能算插件市场安装验收。手动将以下 Stop 条目合并到 `~/.codex/hooks.json`；保留所有已有条目，不直接覆盖文件。路径替换为已解压插件脚本的绝对路径：

```json
{
  "hooks": {
    "Stop": [{ "hooks": [{
      "type": "command",
      "command": "node \"D:/Tools/agent-docs/plugins/codex-agent-docs/scripts/stop.mjs\"",
      "timeout": 10
    }] }]
  }
}
```

重启桌面版并按同样方式审阅 Hook。显式初始化可要求当前 Agent 运行 `node "D:/Tools/agent-docs/plugins/codex-agent-docs/scripts/rules-cli.mjs" init`，读取返回规则后执行。不要同时启用用户 Hook 与插件 Hook，避免收到重复提醒。

### 修改或共享规则

默认用户文件：`~/.agent-docs/codex/init.md`、`maintain.md`。可先运行 `node "<插件目录>/scripts/rules-cli.mjs" info` 创建并查看位置。直接编辑后下次调用生效。

如要与 DSH 共享，在启动桌面应用的环境中设置 `AGENT_DOCS_RULES_DIR` 为绝对目录，并将 DSH rulesDir 指向同一路径。环境变量变化需要重启宿主；规则内容变化不需要。Windows 与 WSL 不自动共享路径。

## 人工验收清单

在临时项目执行，避免把验收内容写到真实项目。以下项目只有实际观察后才能标通过：

1. 无 Docs 的普通轮次：不创建 docs，不被 Hook 续接。
2. 用户明确初始化：创建七个目录与各级 index.md，AGENTS 导航、中文注释规则和 Evidence 忽略约定；已有文件保持原文。
3. 已初始化项目普通轮次结束：原 Agent 收到一次维护提醒，读取实际 maintain.md；续接结束后不再循环。
4. 简单修复与无实质变化：不强制创建 Design/Pending/Evidence；现有 Docs 准确则不写。
5. 真实模块变化：Project 按实现更新，索引同步；未完成/未通过如实说明。
6. 仅设计讨论与规则歧义：Design 和 Project 区分；重要取舍提问，拒绝或未答复不执行。
7. 用户要求本轮不动 Docs：原 Agent 尊重请求，即使 Hook 提醒也不改。
8. 编辑用户规则、升级默认文件：下次读取新用户内容，升级不覆盖。
9. 取消、卸载、重复启用：无额外续接或残留工具；DSH 子 Agent 不触发主工作维护。
10. 与其他 Stop Hook 并存、DSH/Codex 交替工作：无循环，编辑前重读目标文件，无互相覆盖。

若失败，记录宿主版本、实际规则路径、触发输入和观察结果；不要把配置展开或单元测试当作真实模型维护验收。
